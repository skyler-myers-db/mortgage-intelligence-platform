Since post-w5/deploy-hardening (2026-10-27) `tools/databricks/provision_runtime_secrets.py` plans every write first. An existing `cotality-id-mask-v1` must equal the configured `MIP_COTALITY_ID_MASK_SECRET` as the runtime reads it (UTF-8, stripped), compared as HMAC-SHA256 under a per-run random salt; differ, unreadable, or an empty `value` answer (`EmptySecretValue`) -> `RuntimeSecretChangeRefused`, exit 2, nothing written. An existing `genie-action-current` is compared the same way but only NOTED (unchanged / rotated with grace / changed with no grace key / not compared), never refused. Unset `SALESFORCE_*` keeps an existing key; the payload never binds a key whose input is unset (six-input rule), except the placeholder-input edge (provisioner treats `<x>`/`changeme` as unset, the payload as set). `--check` is read-only and runs at the end of the step-0 preflight, before step 0a stops the App.

**Why:** a changed mask re-keys every `B-…` id and orphans the ids stored in Lakebase; the old tool overwrote mip-runtime unconditionally, and the write runs after the App stop. The secrets/get read works only for a workspace admin: `databricks secrets get-secret --help` (CLI v1.10.0) says a normal user gets BAD_REQUEST outside a notebook. The first-round proof here (a nonexistent-key probe returning RESOURCE_DOES_NOT_EXIST) was WRONG as proof: the existence check answers before any caller check. The governance verifier re-proved it on an EXISTING key as an admin (paychex, read-only, booleans only); each read leaves a getSecret audit entry. deploy.sh already requires a workspace-admin deployer, so the guard is viable.

**How to apply:** never add a "rotate the mask" flag to the provisioner; a re-key is an owner data migration. Any new secret that keys persisted data gets the same fingerprint guard and a pre-stop `--check`. Prove a read-path permission on an EXISTING object, never on a missing one. Tests must record the fingerprints (`_record_fingerprints`) and assert none leaks; a bare "value not in message" check let a `.hex()` fingerprint through.
