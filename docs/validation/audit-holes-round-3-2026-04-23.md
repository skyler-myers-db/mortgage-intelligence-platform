## What I searched for but did not find (novel to round 3)

- No outbound email/SMS / Twilio / SendGrid / SMTP in the approve path. CLAUDE.md posture holds.
- No CLIP logging: `backend/services/observability.py` denies `owner_name*` + `mailing_*` + `situs_street*` but does NOT explicitly filter `clip` — it's not logged in any call site grep-check though, so the gap is de-facto closed.
- No dynamic-SQL concatenation of user input: every `execute(...)` call uses named parameters (`:segment`, `%(approval_id)s`). `LIMIT` values are bounded via `_bound_limit()` before string-formatting.
- `gold.borrower_360.evidence_ids` traces to real `gold.evidence_events.evidence_id` UUIDs — `/api/offers/recommend` surfaces them verbatim. Governance contract "every recommendation traces to evidence" holds.
- Circuit-breaker state change logs emit at `WARNING` correctly; resilience.py log levels are well-calibrated.
- AbortSignal plumbing is HALF present: `lib/api.ts` accepts `signal?: AbortSignal` on every method, but most routes (offer-orchestrator at :119, lead-queue, home) don't pass one. Round 2 finding #10 stands.

## Headline takeaways for the master agent

1. **Finding #7 (CURRENT_TIMESTAMP non-determinism)** is the subtle one — breaks parity tests intermittently and means two "refreshed" chips can disagree on the same page.
2. **Finding #8 (CTAS ordering)** is the most dangerous operational gap: a partial refresh silently scores a stale population, and no sentinel catches it.
3. **Finding #12 (no runbook)** is the operator-facing gap. When the first customer pages, Entrada's on-call has no 5-step diagnostic document.
4. **Finding #17 (admin PUT accepts arbitrary JSON)** amplifies Round 1 #8 — the endpoint isn't just in-memory, it's un-schema'd and un-auth'd.
5. **Finding #18 (genie placeholder breaks first call)** is the only BLOCKER-adjacent item — a fresh customer deploy where the operator hasn't set GENIE_SPACE_ID sees `/api/health` say "up" and then the first Ask Genie click 500s.
