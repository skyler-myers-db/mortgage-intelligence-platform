# Committed ZCTA geometry (per state)

One TopoJSON file per state plus DC (`<USPS>.topo.json`, 51 files) and a
`manifest.json`, generated by `tools/geo/build_zcta_topojson.mjs` and drawn by
the geography map's ZIP rung (`USChoroplethMapZctaLevel.tsx`, audit
`dataviz-01` / `visual-09`). The runtime fetches a state's file only when a
user drills into that state on Segment Intelligence, as a hashed,
same-origin `/assets/<USPS>.topo-<hash>.json`; nothing is fetched from the
Census Bureau at deploy time or at runtime.

Status: the operator build is pending. Until the files are committed, every
drill falls back to the densest-ZIP tiles with a status line.

## Provenance

| Source | URL | SHA-256 |
|---|---|---|
| ZCTA cartographic boundaries, 1:500,000 (2020) | https://www2.census.gov/geo/tiger/GENZ2020/shp/cb_2020_us_zcta520_500k.zip | pinned in the tool's `SOURCES` and recorded in `manifest.json` `sources` at the approved build |
| ZCTA-to-county relationship file (2020) | https://www2.census.gov/geo/docs/maps-data/data/rel2020/zcta520/tab20_zcta520_county20_natl.txt | as above |
| State cartographic boundaries, 1:500,000 (2020) | https://www2.census.gov/geo/tiger/GENZ2020/shp/cb_2020_us_state_500k.zip | as above |

The tool refuses any source whose SHA-256 does not match its pin, and refuses
an unpinned source. `manifest.json` records the three hashes, the dependency
versions (from `tools/geo/package-lock.json`), the projection, the
simplification weight, the quantization and, per file, the ZCTA count, bytes,
SHA-256, arc point count and both bounding boxes.
`tests/unit/test_zcta_geometry_manifest.py` checks every one against the files.

## A ZCTA is not a USPS ZIP code

ZIP Code Tabulation Areas are the Census Bureau's generalized areal
representations of USPS ZIP code service areas. They approximate delivery
areas built from census blocks; they are not the USPS's own boundaries, and
PO-box-only and unique (single-organization) ZIP codes have no ZCTA at all.
The map says so in its caption, and its reconcile note lists the ZIP codes
with borrowers but no ZIP-area boundary. A ZCTA that crosses a state line is
drawn in each state it has land in.

This layer is shape-only. Demographic, ACS or composition overlays on it are out of scope and require a fair-lending review.

## Regenerating (operator only; never in CI or deploy)

```bash
npm --prefix tools/geo ci --ignore-scripts
node tools/geo/build_zcta_topojson.mjs --download   # sources go to ~/.cache/mip-geo
git diff --exit-code frontend/src/geo/zcta           # a rebuild of the same sources is byte-identical
```

The other flags are `--source-dir` (default `~/.cache/mip-geo`, never inside
the repository), `--out` (default this directory), `--weight` (the one planar
simplification weight) and `--fixture-pins` (synthetic test builds only: the
manifest then records `fixture_pins`, which the gate refuses). The build
fails, and writes nothing, when a file exceeds 1.5 MiB or 120,000 arc points
or the set exceeds 20 MiB.
